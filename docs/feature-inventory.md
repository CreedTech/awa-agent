# Feature inventory and backend integration plan

This records the product flows present in the frontend before commit `6c8d808` removed local fabricated state. It is a recovery map, not a claim that these flows were production ready. The original UI and transitions are still available in Git at commit `fb7148f` (for example, `git show fb7148f:app/tenant/escrow/page.tsx`). Rebuild each flow against authenticated backend data and server-enforced rules; do not restore the old local data layer.

Baseline backend reference reviewed: `AwaAgent/awaagent-backend`, commit `5b65080`; production health reported build `c6a2357` on 2026-10-08. The baseline mounts `/api/v1/auth`, `/properties`, `/inspection`, `/escrow`, and `/trust`. Its OpenAPI file calls the inspection path `/inspections`, but the mounted route is **`/inspection`**. The table below is the **pre-implementation inventory**; it preserves what was missing when the old frontend screens were removed.

## Current implementation

The backend and frontend have deployed Resend signup/recovery, manual admin KYC, landlord-agent authorizations, Paystack subscription checkout, rent checkout verification, payout recipient setup, signed webhook processing, saved homes, owned listings, profiles, dispute submission and admin decision, refund tracking, role-scoped payment lists, and Cloudflare R2 listing and identity image uploads. Production migrations have run. Resend and Paystack remain unavailable to users until their credentials, callback URLs, admin bootstrap, and live transaction acceptance checks are supplied and completed. R2 uploads require the two buckets, custom image domain, credentials, and bucket CORS rules before use.

The deployed system includes listing editing, landlord listing submission with an authorized agent, admin listing review, inspection rescheduling/cancellation and landlord/admin queues, role dashboards, payment receipts, live subscription pricing, admin account status controls, settings, audit logs and trust flag review. It also includes stored notifications for KYC decisions, inspection booking/rescheduling and listing review; an agent capacity page, a landlord agent matrix, and directions after address unlock. Listing photos and private identity evidence use Cloudflare R2 direct uploads once bucket credentials and CORS are configured. Paystack charge funds go to the merchant account; this is not a separate regulated escrow account. A later Dojah integration can replace manual identity evidence checks while preserving KYC review history.

The deployed follow-up adds a reconciliation queue with audited case notes, an agent unavailable-date calendar enforced by booking, and a tenant rental history derived only from settled payments. The user chose history without points or redeemable rewards, and unavailable dates instead of daily time slots.

The current follow-up adds more stored notifications for payment, payout, refund, dispute, agent authorization, KYC queue and inspection outcomes. It adds agent performance counts and paid commission from actual database records, and limits inspection code attempts. These changes require this follow-up's backend and frontend deployments.

Remaining product work: email delivery for non-auth notifications; provider and bank reconciliation of ambiguous transfers, refunds and historical payments (the queue records review notes but cannot prove bank settlement); a future KYC evidence retention/deletion policy and operator workflow (private documents are retained for now at the owner's direction); geocoded in-app maps beyond external directions; and live provider acceptance testing. These are tracked here so earlier UI concepts are not lost. See [production environment setup](production-environment.md) for all missing credentials and provider dashboard steps.

The public home, `/how-it-works`, `/pricing`, and `/trust-safety` pages also had copy describing planned escrow and verification features as if they were live. Their current copy was narrowed to the connected state. Revisit those pages as the corresponding backend flows launch.

Public `/explore`, property detail, login, tenant inspection list/booking, and agent inspection queue/verification are the connected frontend areas. Where a backend route exists but the prerequisites are not usable (for example KYC or subscriptions), the frontend displays the backend error instead of inventing an entitlement.

## Environment provenance

- The production API URL `https://api.awaagent.b2686bbc.sslip.io/api/v1` came from the backend repository's `openapi.yaml` and `DEPLOYMENT.md`, then was checked against its public health and property endpoints.
- The frontend's Vercel project was already linked in `.vercel/project.json` to `creedtechs-projects/awa-agent`. Existing public branding/support variables were already configured there. During integration, `NEXT_PUBLIC_API_BASE_URL` was added to **Production** and the obsolete `NEXT_PUBLIC_USE_MOCKS` entry was removed. No payment, identity, or other provider secret was created or supplied.
- [`.env.example`](../.env.example) is a committed template for local development. `lib/env.ts` has the production API URL as a fallback. These are public client-side configuration values, not credentials. The backend's private production environment was not copied into this frontend.
